# 三道预检的输入、隔离与判定方式

## 隔离

六个公平性读者和三个完整盲修均在新 agent 中以 `fork_turns=none` 启动，不继承父任务历史。各自只获准阅读相应 `candidates/cX/visible/` 内的 instruction.md 与 app，以及自身输出。没有提供候选机制名、答案、隐藏日、判分器、标准答案、历史交付物或其他读者意见。未向盲修发送任何外部评分反馈。

这是上下文和明确阅读范围隔离；它没有建立操作系统级访问控制，不能声称技术上阻断了一切越界读取。各原始回答声明了阅读范围，工具调用记录可审计；本文件不是完整的 agent 操作转录。

## 公平性

开放式目标是完整回答“这个调度工具应如何修复、物理/成本/时间/可用性约束如何推导、哪些解释明确或存在歧义”，不要求读者对给定答案投票。两个读者相互独立。完整原始回答保存为 reader_cX_a.md、reader_cX_b.md；本目录 READERS_SHA256.json 固定其内容。

| 候选 | 两位读者的新要求推导 | 原始回答 |
|---|---|---|
| C1 | 由同一稳态接入点的净有功决定进口/出口，价差下不得同时为正 | [a](reader_c1_a.md)、[b](reader_c1_b.md) |
| C2 | 39.6/3.6=11 kWh(gross)/Sm³；四台共用入口 ≤550 Sm³/h 即 6050 gross kW | [a](reader_c2_a.md)、[b](reader_c2_b.md) |
| C4 | PHE1 一次侧 20×4.18×20=1672 kW；先减 AC 驱动热，不能误限所有 HT | [a](reader_c4_a.md)、[b](reader_c4_b.md) |

六份报告均保留其全部限定与异议。有关既有母管温度控制、辅助排热、PV/出口边界的意见不能被删掉，再声称读者对完整现实工程模型全无异议。C4 两位都指出回路温度作为模型运行工况的前提；若被解释成可任意偏离的名义设计值，流量上限不能直接成为固定热功率上限。这里的新要求读法收敛不代替正式公平审查。

## 完整盲修

各盲修被要求尽最大努力完成一般同结构输入的完整工具，依赖仅 Python 标准库、NumPy、SciPy，保持 CLI/输出结构、两分钟以内和确定性。要求自己建立检查器、独立验证并生成有代表性的测试日；没有限成一次草稿、仅可见日或不许自检。固定本轮运行环境提供 Python 3.13.16/NumPy 2.3.4/SciPy 1.17.0。

写完自检与说明后，盲修必须将全部交付 SHA256 写入自身 FREEZE.json，声明冻结。父任务仅在声明后读取实现和实施外部评测；随后不得根据隐藏反馈修复它。为了不把不同角色共享同一推理上下文，没有让公平性读者兼任盲修者。

提示预检看的是“是否正确处理新增规则”。即便整套任务因旧难点或其他原因失败，只要新增规则已正确建模并通过实际有约束的输入，也不能把它记为新难点成功隐蔽。相反，仅在新限制不绑定的可见日出一个合法计划，不足以认定已处理新增规则。

## 历史难度回放

C1/C2/C4 对两份原强工具均零适配，以原目录实际运行。每个固定日两次执行，独立参考重算物理、成本和全部断言。新字段正常读取而被忽略，和解析错误有明确区别。所有已计入 E 的失败都发生在可行日；两强固定回放耗时远低于 120 秒。

因果控制代码位于 audit/arbitrage/diagnostic-direction-fixed，它增加正确购售方向理解，专用于确认根因，绝不是格式适配。正式 E 回放始终使用原交付物。
