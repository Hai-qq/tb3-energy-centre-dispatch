## 1. 新水流量规则确实进入优化、审计和独立整日模型

| 层次 | 冻结实现中的处理 | 源码位置 |
|---|---|---|
| 可见参数读取 | 读取 `heat_exchangers`，验证一次侧是 `engine_ht`、二次侧是 `lthw`，且换热器存在于两侧连接表中 | `blind/app/planner/plant.py:134,201–215` |

| 独立整日 MILP | 用另一套分段二元变量/插值权重形成 HT，独立构造 `phe = ht − absorber_heat`，设置 `[0, phe_capacity]` 及建筑供热等式 | `blind/checks/optimality_oracle.py:173–182` |
| 作者原始解释 | 明确写出 `20 × 4.18 × (90 − 70) = 1672 kW`，并说明 PHE 检修移除该传热通路 | `blind/README.md` 的 PHE rating 行 |

生产 LP 使用的是分段仿射热量。令 `ht_constant` 为所有运行发动机所在分段的 HT 截距，则实际 PHE 热量为 `phe_flow @ x + ht_constant`。实现分别写入 `-phe_flow @ x <= ht_constant` 和 `phe_flow @ x <= capacity − ht_constant`，所以其下限与上限均包含正确截距，没有把单纯斜率项错当成总 HT。

它没有将 1672 kW 套在发动机全部 HT 上，也没有把一次、二次侧供水温差 `90−80` 当成主侧沿程温降。对本候选唯一的 PHE1，停机、连接端点及已定义最大质量流量均进入容量函数。

## 2. 独立性、完整程度与证据边界

### 2.1 两种优化建模确实不同

生产工具对各半小时的发动机承诺状态、相邻性能段及 AC 冷却水入口工况作枚举。每个区域是线性约束加进口视在功率圆；`_circle_lp()` 通过真实圆的外切支持半平面逐次细化，只有候选满足实际圆和线性残差容差才接受。全日动态规划再计入所有开机转移及午夜状态。最终计费从实际选定设备出力复算，并与优化目标交叉核对。

独立 `optimality_oracle.py` 不导入 `planner`。它在一个全日模型中使用分解的发动机分段二元变量和插值权重，显式建模各期启动状态、冷却水工况、PHE 分流及所有经济项。参考费用使用 `mip_dual_bound`，即求解器提供的下界；连接圆仍通过外切支持约束形成可认证下界。作者将通过独立物理检查的计划与此下界比较，容差为 £0.0002。

因此，独立 oracle 不只是再次调用生产优化器，也没有拿生产输出反填目标值。但“独立”仍应限定：两者都使用 SciPy/HiGHS 后端；整日 oracle 从 `verify_plan.py` 复用了输入读取、插值、可用性、燃气换算及电价辅助函数。它们还共享了下文的旧检修建模遗漏。这是独立优化结构与独立于生产的检查代码，不是完全不同的物理假设、求解器或形式化证明。

## 3. 旧检修缺口：解析连接关系，但未传播部件停机

生产 `_available(day, unit_id, hhmm)` 只精确匹配传入的 `unit_id`，见 `optimize.py:29–43`。上游调用检查发动机本体、锅炉本体、冷机本体、AC 本体、LT 出口散热器、塔、PHE 和 PV，却没有同时查询可见热路中的部件端口：

- `GE1/GE2 jacket water and exhaust` 与 `GE1/GE2 intercooler` 的停机没有令对应发动机不可用。
- `EC1/EC2 condenser` 的停机没有令对应电制冷机不可用。
- `AC1 generator` 或 `AC1 absorber and condenser` 的停机没有令 AC1 不可用。

`Plant` 确实利用这些字符串识别了热路归属，见 `plant.py:138–159`；但静态“已连接”标志不能代替当前半小时的部件可用性。该实现忽略这些合法检修项继续出计划，与 C1 盲修“遇未知部件名立即拒绝”的缺陷表现不同。

自己的检查器在 `verify_plan.py:123–129,186–199` 同样只查设备本体和 LT 散热器；自建 MILP 在 `optimality_oracle.py:90–95,132–147` 也复制了这个物理层面的覆盖缺口。因此三个模型在自测中一致，不表示这个旧难点已经做对。

名字为 `every_plant_outage_category` 的自测仅覆盖 B1、EC1、AC1、CT1、PHE1、PV1、LT radiator 1。它没有逐个覆盖所有热路端口名称，不能把该场景名称当成完整部件覆盖的证据。

## 4. 公共母管与公平前提的保留

C4 盲修主动允许公共冷凝水高于最低有效温度。其共同温度消元沿用可见正值、连续、非增 COP 表：给定各冷机冷量后，总压缩机功率是公共水温的连续非减函数，因此两个温度端点给出的总功率区间可由某一共同温度实现。生产与独立检查均从电力平衡恢复实际压缩机功率，而不是让各冷机独立选温度或凭空添加电负荷。

其 `heat_led_cooling_water_modulation` 是作者冻结前自行构造的热需求/出口限制反例；不能把这项旧范围的控制差异误判为 C4 新规则遗漏。当前外部固定日只有检修可用性断言失败，已清楚区分两者。

另一方面，PHE 的 1672 kW 推导仍依赖把可见 90/70°C 视为给定运行温度。两位公平读者保留的“设计温度还是固定运行工况”条件仍然存在。一个盲修成功采用同一读法证明新规则容易被识别，不能替代独立的无歧义公平审查。即使将来补充运行温度约束消除该风险，本次提示预检已经说明现有 C4 容量字段没有形成合格的新隐蔽难点。
