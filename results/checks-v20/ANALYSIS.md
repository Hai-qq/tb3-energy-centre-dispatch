# v20：可复算的共同错误，与新一轮模型难度的区别

## 范围与证据纪律

本轮以 `9db580817b1dc46ac6c500f8c472faaafce0a997` 为唯一基线。所有新实验、完整可见包、参考模型、盲读原始回答及计划均保存于 `results/checks-v20/`。本文件与 `LOG.md`、机器可读矩阵共同构成交付；历史结果和 archive 未改。

本文中的“强工具”只指已经冻结的两份交付物：v16 第 2 场 Claude（A16）和 v19 第 2 场 Claude（A19）。它们在某日失败不是一次新的模型试跑，更不是一次独立的 Opus/GPT 推理样本。盲修来自本会话的隔离上下文，不是审阅人将运行的 Opus 5.5 max / GPT-6.1 Sol xhigh 正式 3+3。

**费用参考的边界：** v19 的物理检查接受可实现的较暖公共冷凝水及 AC 辅助排热的不同合理口径，但参考 MILP 只优化最低许可水温与较严格辅助排热口径。本轮保留这项既有宽验收/窄费用参考结构。下文的 MILP 数值是该固定口径的整天最优值，也是更宽验收集合中一个可达到的费用上界；不是对所有被接受运行解释的全局最优证明。B 的 £0.001 检查证明标准答案与独立**同口径** MILP 一致。E 中“多付”指相对于已证明可行的较便宜方案，因而是实际失优的证据，而不是声称已经求得更宽模型的精确遗憾值。

## 第一阶段问题一：(a)–(d) 是否已没有公平改法？

**没有；存在一个无需增加字段的反例。** 两强及旧参考 MILP 都把进口 I 和出口 X 当成可以同时为正的连续变量，隐含依赖“所有进口价不低于出口价”。把现有夜间进口价改成 7p/kWh、出口改成 12p/kWh，就破坏了这一隐含条件。格式完全相同，对手零适配；正常医院可见日也能暴露真实错误。

唯一新后果不是“英国电表半小时两个寄存器绝不可能都增长”。可见 `dispatch.py` 已要求每个设备出力 **held for the whole half-hour**；在这个稳态半小时模型中，一个接入点的有功交换是同一个有符号数：`I=max(Pnet,0)`、`X=max(-Pnet,0)`。若现实中允许半小时内改变出力，两个累计寄存器可能都增长，那是另一个运行模型。没有拿计量惯例来偷偷补题意。

相反，在诊断副本中仅让原半小时 LP 分别求“只进口”和“只出口”，两强都恢复五日全过，见 `candidates/c1/causal-direction-fix/`。它们是增加正确理解的因果修复，明确不属于给对手的最小格式适配。另有恒定 1250/2000/500 kW 机制隔离日，两强的真实次优约 £42.23/£42.77，见 `audit/arbitrage/`。

因此，375 个只改隐藏日、保持旧电价的成功回放不能推出“所有原字段取值均健壮”。但这同样不能推出“新一轮仔细实现者不容易识别购售价差”。后者必须看冻结盲修。

## 第一阶段问题二：强做法的假设与边界

完整逐文件、逐行审计在 [STRONG_IMPLEMENTATIONS.md](audit/STRONG_IMPLEMENTATIONS.md)，包括约五十项规则以及未使用字段。主要发现如下。

| 范围 | 两强真正使用的规则 | 已测边界 / 不应夸大的地方 |
|---|---|---|
| 部件归属 | 机组 id + 空格前缀；LT 中冷器沿热路出口寻找散热器 | 当前命名与一跳拓扑足以通过，任意改名不能公平否定 |
| LT 多出口 | A16 要求所有出口可用；A19 任一出口可用 | 两者并不等价；并联实验只击破 A16 |
| HT/LTHW | 当前所有发动机 HT 合成一个池；AC/PHE 分流；PHE 无容量时可无限传热 | 新的 PHE 一次侧流量上限两者均遗漏；h2 超限约 31% |
| 母管 | 比较自然最低温与 AC 最低入口温；按公共温度计算电冷机 COP | 旧低温锁定已被修；AC 辅机排热的两种解释原已接受 |
| 设备性能 | 枚举所有相邻发动机性能段，正确处理非凸分段；COP 插值 | 改中间曲线点通常不足以击破，不应再当成首尾线性化错误 |
| 电力 | 正确扣发动机固定 PF 无功；检查负无功；进口/出口 LP 变量却不互斥 | 新电价给出共同语义漏洞；underexcited 等只会单破或 parser 拒绝 |
| 燃料 | 正确 net/gross 换算、锅炉效率和能量计费 | 新共享入口标准体积上限没有进入模型；h2 两强同为约 596.34 Sm³/h |
| 电气支路 | 只检查总接入容量，无独立冷机馈线 | 三冷机 400 kVA 不绑定；更小值有不可行日，不能这样制造难度 |
| 时间耦合 | 全日动态规划只记发动机开停状态和启动费 | 这是给定模型的正确结构；不能暗加爬坡、最短运行或储热终态 |
| 报告 | A16 购售净额化，A19 原样输出 LP 变量 | 净额化可以隐藏虚拟交易，不能撤销假套利已经扭曲的机组选择 |
| 未用字段 | dry bulb、LT 热表、各回路 return 温度等目前多不参与容量约束 | 没有性能图时“不使用”未必错误；只有新增充分数据才能合理约束 |

旧代码的 guard/reject 也不能冒充物理难度：新增拓扑使 A19 拒绝读入，必须先区分只是解析适配还是实际模型错误。本轮 C1/C2/C4 均无需适配，直接运行原路径；执行成功后由成本或实体容量检查判负。

## 第一阶段问题三：五个候选

### C1：原字段电价反转

- 可见变化只有 `supply.json`：工作日及周末 00:00–07:00 从 13.8→7.0 p/kWh；出口从 5.9→12.0。其他日期、预测、状态、设备、代码、instruction 全不变。
- 导出的约束是一个稳态接入点只有一个净有功方向。独立 oracle 分方向 LP，独立整天 MILP 加每半小时方向二元变量。
- 真实性：[Drax 商业 CHP PPA](https://energy.drax.com/sell-power/)提供固定、浮动及定制 PPA；[Octopus 商业分时公式](https://octopus.energy/help-and-faqs/articles/how-calculate-prices-shape-shifters-agile/)将采购价与批发价格挂钩。来源支持采购与出口分别定价这一机制。**7p/12p 是合成合同，未声称存在该医院套餐。** 没有用住宅 EV 价或限小型光伏的套餐冒充 NHS CHP 合同。
- 公平原文：`dispatch.py` 的 “held for the whole half-hour”；`supply.json` 的原有 `import_rates_p_per_kwh`、`export_rate_p_per_kwh` 及一个进口容量/出口上限。
- 实验：五日 oracle、两强与七历史失败工具、43 个变异、3×16 fresh、至少 200 日差分、两读者及冻结盲修。详细结论见本文最终预检结果和验收汇总。
- 风险：新电价非常容易使完整自检注意到互斥；若盲修正确建模，应依用户规则淘汰。默认 HiGHS presolve 的参考差异已单独留证并通过独立可行计划定位，不计作对手失败。

### C2：共同燃气入口的标准体积能力

- 唯一可见文件变化是 `supply.json` 的 `gas.entry`，字段完整定义供应 GE1/GE2/B1/B2、最大 550 标准 m³/h、15°C、1.01325 bar absolute、gross CV 39.6 MJ/标准 m³。
- 推导：39.6/3.6=11 kWh(gross)/Sm³，合计 gross 燃气功率 ≤6050 kW。发动机 net 乘 1.108，锅炉已经是 gross，不能再转换；不是每台各得 550，也不是只算发动机。
- 真实性：[苏格兰政府的 NHS Foresterhill 能源中心案例](https://www.gov.scot/publications/annual-state-nhsscotland-assets-facilities-report-2012/pages/9/)记载额定能力的燃气 booster；[National Gas 方法文件](https://www.nationalgas.com/sites/default/files/documents/Gas%20Demand%20Forecasting%20Methodology%202020_v1.pdf)给出 39.6 MJ/m³ 的建模参考值。550 是合成站点的标准状态服务上限。Honeywell 的 650 m³/h 铭牌是**工作状态**体积，不能直接充当标准体积上限；研究记录明确保留此区别。
- 实验：五日全部可行，h2 MILP £8973.720101；两强均有 7 个时段超入口，峰值 596.338078 Sm³/h，超过上限 46.338078。各 44 个变异全部抓住，包括“忽略入口”和“只计发动机”。
- 公平原文是上述字段，不需 instruction 加句子。风险是字段本身非常显眼；一次标准单位换算不应被包装成深层领域难点。

### C3：冷机馈线的局部视在功率

- `plant.json` 新增馈线及三台冷机 PF=0.9 lagging，完整列出馈线负载和零其他负载；全站无功预测保持原口径，馈线无功属于其分量，不能重复加到全站。
- 真实性：[NHS HTM 06-01](https://www.england.nhs.uk/wp-content/uploads/2021/05/Health_tech_memo_0601.pdf) §10.45 讨论为大型冷机站等独立负载配置 package substations；厂家有真实 400 kVA 量级。合成参数不声称对应某医院具体设备。
- 实验：原三冷机 400 kVA 不绑定；315/350 使 h1 无解；375 在五日都不改变最优。追加只供 EC1 的 200/250 kVA 方案均可行并改变夏日最优，200 kVA 下 h1 费用由 £6426.647467 到 £6453.644088。见 `remaining-screens/results.json`。
- 限制：这一方向完成了参数/可行性数值筛选，未完成两读者、盲修或完整对手预检，**不宣称三道通过**。筛选参考使用角度切线近似；没有拿其小额成本差当作已认证难度。若继续，需要明确 hard continuous limit 并重新冻结可见包。

### C4：PHE1 支路的水流量能力

- `plant.json.heat_exchangers` 定义 PHE1 一次侧 engine_ht、二次侧 lthw、一次侧最大 20 kg/s、cp=4.18 kJ/(kg K)。原 engine_ht 90/70°C 未改。
- 推导：`20×4.18×(90−70)=1672 kW`；约束的是 `HT总热−AC驱动热`，不是全部 HT，也不是 `90−80` 两端温差。
- 真实性：[Alfa Laval 换热理论](https://www.alfalaval.com/globalassets/documents/microsites/heating-and-cooling-hub/alfa_laval_heating_and_cooling_hub_the_theory_behind_heat_transfer.pdf)给出质量流量、比热和温差的热功率关系；[AEL 的医院 LTHW 换热器说明](https://aelheatexchangers.co.uk/central-heating-system-break-heat-exchangers/)支持设备用途。20 kg/s 是合成选型值，不是摘录的 NHS 铭牌。
- 实验：15 kg/s 的 h2 无解，已弃；20 五日全部可行，h2 MILP £9107.675896。两强在 h2 各有 19 个时段超限，峰值 26.196172 kg/s。44 个变异全被抓，包括“忽略限制”和“误限全部 HT”。
- 风险：若供回水温度只当名义设计温度、允许任意改变回水，本上界不能唯一成立。隔离读者按文件给定运行温度推导，并明确指出这个边界；不以现实完整变温模型的缺参来暗加硬约束。新字段同样可能直接暴露解法。

### C5：GE1 的并联 LT 散热出口

- `plant.json` 为 GE1 增加 `LT radiator 3`，显式 parallel、individually isolatable，每只散热器 250 kW，足以容纳单台发动机全部 LT 热。
- 实验：A16 h2 多付 £271.985428，h4 多付 £41.350645；A19 五日全过。原始计划和两次执行在 `remaining-screens/`。
- 已淘汰：不能击破两强；精确的 NHS 并联 CHP LT 散热器一手出处仍缺失。没有把一般 N+1 设计或电气备用资料冒充这种热路的真实性证明。该候选不进入盲修或任务目录。

## 第一阶段问题四：通过率、漏读概率与 3+3

历史仍是 Opus 2/10、GPT 0/6；版本、停止规则与样本量使其不是可靠同分布频率估计。尤其 0/6 不意味着 pGPT=0。固定代码在 200 天重复遗漏同一条约束，仍然只反映这份代码的一次建模选择，不能按 200 次独立模型失败更新概率。

若假定未来单场通过率为 pO、pG，且六场条件独立，才有：

`Pr(3+3全挂) = (1−pO)^3 (1−pG)^3`。

| 假设 pO | 假设 pG | 条件下 3+3 全挂 |
|---:|---:|---:|
| 20% | 10% | 37.3248% |
| 10% | 5% | 62.5026% |
| 5% | 2% | 80.6954% |
| 1% | 1% | 94.1480% |

相同通过率时，要达到 95% 的六场全挂概率，单场通过率需低于约 0.8512%。本轮数据不支持这种精度的承诺。以下补充冻结后判断；不会把运行失败、旧难点错误或求解器配置差异当成新推理难点被漏掉。

### 各候选的漏读概率：只给主观规划区间

这里的 q 指“原本有能力完成 v19 的一次新实现，遗漏或错误实现新增要求”的概率；不是整题失败率。没有目标模型新样本，不能估出 Opus 与 GPT 的不同参数。为回应预算规划问题，下面给出**主观、未经校准的宽区间**，两模型采用相同区间，不是置信区间、后验概率或正式试跑预测。范围之外的真实值仍完全可能。

| 候选 | q Opus | q GPT | 判断依据与限制 |
|---|---:|---:|---|
| C1 | 10–30% | 10–30% | 两旧工具同错，但两读者与完整盲修都识别；现有三值反转足以触发方向检查。新从头实现比沿用旧LP更可能发现 |
| C2 | 5–20% | 5–20% | 一个完整列供应对象的资源入口与一次单位换算；盲修甚至自行生成锅炉参与的绑定日。没有依据给它很高隐蔽性 |
| C3 | 不可估 | 不可估 | 原400kVA包不绑定，对固定五日的新增失败贡献实测为零。单EC1的200/250版本只有数值初筛，不能拿未做的提示预检估计目标模型概率 |
| C4 | 10–30% | 10–30% | 需要同侧温差及扣AC支路，比单入口略复杂，但两读者与盲修均正确，且仍有温度口径公平性条件 |
| C5 | 0–30% | 0–30% | 仅表示若补足来源并重做完整预检时的粗略假设；现有A19已全过，不给当前候选任何合格性或稳定性信用 |

这些判断无法由一次替身直接统计得到；它们的用途是防止把“旧代码100%失败”误译成“新模型近乎必败”。对于缺少完整预检的 C3，拒绝编造数字比假精确更符合实验状态。

若额外假定新增字段不改变旧题能力，且新错读与旧错误独立，才有 `pO_new=pO_old×(1−qO)`，GPT 同理。仅作敏感性演示，取 pO_old=20%、pG_old=10%（后者是**人为假设，绝非从0/6估计**）：C1/C4 区间对应 pO_new约14–18%、pG_new约7–9%，3+3全挂约41.55–51.16%；C2约16–19%、8–9.5%，3+3全挂约39.39–46.15%。没有任何一项接近支持“稳定全挂”的程度。

更关键的是独立性假设未证：显眼的新字段可能促使作者更仔细地处理旧母管与检修，反而提高整题通过率。因此上述是条件场景计算，不能作为采用候选的理由；本轮实际采用门槛仍由三道预检决定。

## 不重做的方向与下一步边界

HARDENING 已亲自复核：exactly-once gateway、批量场景提速、周计划加储热与最短开停机均有既有证伪实验；尤其后者的近似 DP 加 MILP polishing 已在预算内达到容差。储热在 NHS 确实存在，并不使它成为本轮新的未试方向。本轮未重新跑这些原型，未把旧结果说成本轮新实测。

不能从五个候选断言所有可能任务结构已经到顶；也不能因“新容量规则击破旧代码”就推荐正式 3+3。只有读者理解收敛、旧强真错、盲实现仍漏掉新要求这三件事同时成立，才适合按用户规则采纳。

## 候选资格与实际交付边界

[DECISIONS.json](prechecks/DECISIONS.json)逐项区分“预检完成”“预检通过”“新要求已解决”和“整题失败”。C1/C2/C4完成三道预检，均因新要求被盲修解决而淘汰；C3只有实际数值初筛；C5被A19全过与真实性缺口淘汰。没有把五个探索方向写成五个合格候选。

因此本轮的最好反例是C1：它推翻了“(a)–(d)不可能公平击破两份旧强”的过强结论，也获得了完整200日四方差分证据；它却**没有**通过用户要求的新模型提示预检，不能晋级正式v20。正式任务保持v19逐字节一致，交付分支保存全部可运行候选、验证工具及负结果，而不是伪称已完成稳定3+3全挂的加固。

从三份新规则被识别，不能证明任务结构已经到顶，也没有理由把C1/C2/C4简单相加后跳过新的提示预检。若要继续，应先提出具有充分NHS工程出处、数据能唯一决定后果且不重复已证伪机制的具体包，再从两位独立读者和一次完整冻结盲修开始；不应先写入正式任务再替它补资格。
